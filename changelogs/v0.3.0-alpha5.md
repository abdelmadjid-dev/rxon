# RxOn v0.3.0-alpha5 Release Notes - "Elegant & Streamlined Pipelines"

This release delivers significant API refinement, shifting the library to a clean, single-generic parameter model that drastically reduces generic signature noise while offering powerful state merging, smart branching, segment resilience, and stacktrace filtering.

## New Features & Key Refinements

### 1. Simplified Generic Architecture
Transitioned from the dual-generic `Work<T, C>` and `Observe<T, C>` signature to a clean, single-parameter `Work<T>` and `Observe<T>`. This eliminates the need to carry unused context types throughout your codebases.

### 2. Explicit State Merging
Chaining operators (`thenFunction`, `thenSingle`, etc.) have been extended with overloads that accept a `BiFunction<T, R, U> merger`. This empowers the developer with explicit control to propagate or combine previous pipeline values down the chain:
```java
Work.callable(WorkScheduler.IO, () -> fetchUser())
    .thenFunction(
        WorkScheduler.COMPUTE,
        user -> transform(user),
        (user, transformed) -> new UserState(user, transformed)
    )
```

### 3. Smart Branching (`thenBranch`)
Introduced `thenBranch(condition, onTrue, onFalse)` for elegant, declarative conditional orchestration:
```java
Work.callable(WorkScheduler.COMPUTE, () -> request)
    .thenBranch(
        req -> req.isValid(),
        Work.callable(WorkScheduler.IO, () -> process(req)),
        Work.fail(new IllegalArgumentException("Invalid request"))
    )
```

### 4. Segment Resilience Blocks
Native support for grouping multiple preceding pipeline stages collectively under a single resilience policy using the `resilience()` block:
```java
Work.callable(WorkScheduler.IO, () -> service.callA())
    .thenFunction(WorkScheduler.IO, a -> service.callB(a))
    .resilience(policy -> policy
        .retry(3, 100, BackoffStrategy.EXPONENTIAL)
        .timeout(5, TimeUnit.SECONDS)
        .fallback(Work.callable(WorkScheduler.COMPUTE, () -> Fallback.INSTANCE))
    )
```

### 5. Functional Composition
Added the `.compose(transformer)` operator, enabling clean reuse of pipeline fragments or utility pipelines across different parts of the application:
```java
Function<Work<String>, Work<String>> logAndAudit = 
    work -> work.log(LogLevel.INFO).thenAction(WorkScheduler.IO, () -> auditService.track());

Work.callable(WorkScheduler.IO, () -> "data")
    .compose(logAndAudit)
```

### 6. Parallel Execution and Iterables
- **`Work.allOf(WorkScheduler, List<Work<T>>)`**: Execute multiple work pipelines in parallel and collect their results.
- **`Work.forEach(WorkScheduler, Iterable<I>, Function<I, Work<R>>)`**: Execute a work pipeline sequentially over a collection.

### 7. Stacktrace Cleaning
Drastically reduced diagnostic noise from internal reflection, system lambdas, and RxJava internal wrappers by filtering the exception cause chains under `RxOnConfig` debug settings.

## Breaking Changes
- `Work<T, C>` is now `Work<T>`.
- `Observe<T, C>` is now `Observe<T>`.
- Removed `pushContext()`, `zipContext()`, and `setContext()` operators as implicit context propagation is deprecated in favor of explicit merger functions.
