# Release Notes - v0.2.2

RxOn v0.2.2 introduces a refined chaining API to eliminate lambda ambiguity and improve type inference without requiring explicit casts.

## API Refactor: Unambiguous Chaining
The DSL now uses distinct names for different types of asynchronous composition. This allows the Java compiler to automatically resolve the correct functional interface:

- **`then()`**: Exclusively for **synchronous transformations** (Map).
- **`chain()`**: Exclusively for **Work/Stream composition**.
- **`chainSingle()`**: For chaining RxJava **Single** sources (Work only).
- **`chainCompletable()`**: For chaining RxJava **Completable** sources (Work only).
- **`chainPublisher()`**: For chaining **Reactive Streams Publisher/Flowable** (Stream only).

## Operator Renaming (Semantic Consistency)
To maintain a consistent "chain-first" terminology for asynchronous operations, several conditional operators have been renamed:
- `thenIf` -> **`chainIf`**
- `thenOnlyIf` -> **`chainOnlyIf`**

## Infrastructure
- Removed all redundant explicit casts from internal delegations and unit tests.
- Standardized `IllegalStateException` messages to reflect the new operator names.

## Bug Fixes
- Resolved all "reference to chain is ambiguous" compiler errors.
- Fixed Javadoc `@link` references across the entire library.
