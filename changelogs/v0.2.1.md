# Release Notes - v0.2.1

RxOn v0.2.1 focuses on maturing the Semantic DSL by unifying all chaining operations under the `then()` operator and improving the developer experience with checked exceptions.

## Semantic DSL Enhancements
- **Unified `then()` Overloads**: The `then()` operator is now an overloaded "Swiss Army Knife" for chaining:
    - `then(WorkScope)` / `then(StreamScope)`: For composing Work or Stream stages.
    - `then(ThrowingFn)`: For direct synchronous transformations (mapping).
    - `then(AsyncScope)` / `then(AsyncCompletableScope)`: For direct integration with RxJava `Single`, `Completable`, and `Publisher`.
- **Side-Effect Transitions**: Added support for side-effects that consume a value but transition the chain to `Work<Done>`.

## Infrastructure & DX
- **Specialized Functional Interfaces**: Introduced `WorkScope`, `StreamScope`, `AsyncScope`, etc. These allow the Java compiler to disambiguate lambdas based on their return type in most common scenarios.
- **Checked Exception Support**: All DSL functional interfaces now throw `Throwable`. This matches RxJava 3 signatures and allows you to call methods that throw checked exceptions (like `IOException`) directly within your pipeline without manual try-catch wrapping.

## Bug Fixes
- **Javadoc Resolution**: Fixed broken `@link` references in deprecated methods caused by the v0.2.0 DSL refactor.
- **Internal Delegation**: Fixed recursion and ambiguity issues in internal delegations of `switchOn`, `on`, and `compose`.
- **Null Validation**: Standardized null-check logic across all new overloads using `Objects.requireNonNullElseGet`.

## Deprecations
- Legacy operators like `on`, `onAsync`, `compose`, and `switchOn` remain deprecated and link to their new `then()` equivalents.
