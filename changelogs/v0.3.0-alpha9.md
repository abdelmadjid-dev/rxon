# RxOn v0.3.0-alpha9 Release Notes - "Engine Statelessness & Terminal Reliability"

This release delivers the "Engine Statelessness" architectural refactor, transitioning RxOn to a strictly value-based pipeline engine with single-generic parameters, explicit state merging, centralized terminal execution via `PipelineSubscriber`, new asynchronous emitter factories, and enhanced stacktrace cleaning.

## Key Features & Enhancements

### 1. Stateless Engine & Single-Generic Architecture
Simplified the core engine by stripping internal context storage and state propagation logic:
- `Work<T>` and `Observe<T>` are now strictly single-generic abstractions.
- `PipelineResult` and `PipelineException` no longer carry context state.
- `PipelineCompiler` and `ObserveCompiler` operate purely on values, significantly reducing internal pipeline overhead.

### 2. Explicit State Merging
All chaining operators (`thenFunction`, `thenSingle`, `thenCallable`, etc.) support explicit `BiFunction<T, R, U> merger` overloads. Developers retain full control over state combination across stages without implicit context luggage:
```java
Work.callable(WorkScheduler.IO, () -> userRepository.getUser(userId))
    .thenSingle(
        WorkScheduler.IO,
        user -> accountRepository.getAccount(user.getId()),
        (user, account) -> new UserProfile(user, account)
    );
```

### 3. Centralized Terminal Execution (`PipelineSubscriber`)
Unified error mapping and diagnostic cleaning across all terminal operations:
- All execution entry points (`execute()`, `executeOn(...)`, `trigger(...)`) automatically route thrown errors through `RxOnConfig.mapError()` and the active `StackTraceCleaner`.
- Ensures consistent diagnostics regardless of how the pipeline is executed or observed.

### 4. New Emitter Factories & Time Utilities
Added first-class factories for callback-based integration and timing control:
- **`Work.completableEmitter(WorkScheduler, Consumer<CompletableEmitter>)`**: Wrap asynchronous callback APIs into Completable Work pipelines.
- **`Work.singleEmitter(WorkScheduler, Consumer<SingleEmitter<R>>)`**: Wrap asynchronous callback APIs returning single results.
- **`Work.timer(WorkScheduler, long delay, TimeUnit unit)`**: Construct timer-delayed Work pipelines.
- **`Work.delay(WorkScheduler, long delay, TimeUnit unit)`**: Introduce explicit stage delays.
- **Custom Timeout Exceptions**: `Work.timeout(long, TimeUnit, String/Throwable)` allows specifying customized timeout error instances or descriptions.

### 5. Enhanced Stacktrace Cleaning
`StackTraceCleaner` has been upgraded to recursively unwrap nested assembly wrappers (`AssemblyException`, `OnAssemblyException`, synthetic lambdas) to provide clean root cause diagnostics directly to error mappers and loggers.

### 6. Build Infrastructure
Resolved Gradle configuration cache compatibility when auto-configuring project Git hooks.

---

## Breaking Changes
- `Work<T, C>` and `Observe<T, C>` have been refactored to `Work<T>` and `Observe<T>`.
- Removed legacy context-passing methods (`pushContext`, `setContext`, `zipContext`). Use explicit `BiFunction` merger overloads instead.
- `PipelineResult.getContext()` and `PipelineException.getContext()` have been removed.
