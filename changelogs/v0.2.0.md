# RxOn v0.2.0 Changelog

## Features and Enhancements

*   **Unified Pipeline DSL**: The DSL has been overhauled to provide a consistent naming convention across both `Work` and `Stream` components.
    *   Introduced `start(...)` as the universal entry point, replacing legacy `on()`, `onAsync()`, and related methods.
    *   Introduced `then(...)` as the universal chaining operator, replacing `on()` and `switchOn()`.
*   **Semantic Early-Return Mechanism**:
    *   Introduced the `finish(value)` operator to allow immediate, successful termination of a pipeline, bypassing downstream operations.
    *   Added conditional operators `thenIf` (for `Work`) and `thenOnlyIf` for explicit flow control and pipeline guarding.
*   **Improved Interoperability**:
    *   Introduced `asTerminalSingle()` (for `Work`) and `asTerminalFlowable()` (for `Stream`) to facilitate integration with standard RxJava frameworks. These operators automatically resolve internal signals, such as early completions.
*   **Zero-Argument Chaining**: Added specialized functional interfaces to resolve method ambiguity and improve lambda inference during the composition of zero-input or zero-output workflows.

## Deprecations

*   **Legacy DSL Operators**: Methods including `on()`, `onAsync()`, `switchOn()`, `halt()`, and `composeOn()` have been marked as `@Deprecated`. These methods are scheduled for removal in future releases. Developers should migrate to `start()`, `then()`, and `finish()`.
*   **Safe Interop Methods**: `asSafeSingle()` and `asSafeFlowable()` have been deprecated in favor of the more semantically descriptive `asTerminalSingle()` and `asTerminalFlowable()`.
*   **Unit Type Replacement**: The internal `Unit` type has been replaced by `Done` to provide better clarity for operations that do not return a value. Methods relying on `Unit` (such as `onUnit`) are now deprecated.

## Maintenance and Cleanup

*   Removed obsolete sample code from the `app` module to consolidate validation logic within the core library test suite.
*   Refactored the `WorkTest` and `StreamTest` suites to serve as comprehensive, Java-only technical documentation and validation for the semantic pipeline architecture.
