# RxOn v0.3.0-alpha3

## Semantic Flow Control & Stability

This release introduces semantic flow control operators and finalizes the stabilization of the pipeline orchestration engine, specifically focusing on early termination and SAGA-style compensations.

### Breaking Changes
- **Deprecated `Work.finish()`**: Use `Work.breakWork()` or `thenBreak()` instead.
- **Internal API Change**: Renamed `FinishStage` to `BreakStage`.

### New Features
- **Semantic Breaks**: Added `breakWork(value)` (static) and `thenBreak(value)` (instance) to signal successful but early pipeline termination.
- **Pipeline Recovery**: Added `recoverBreak(recoveryValue)` to allow resuming a pipeline that was previously "broken" via `breakWork()`.
- **Semantic Passthrough**: Added `continueWork(value)` and `thenContinue(value)` for explicit value injection/passthrough.
- **Side-Effect Sub-pipelines**: Added `peekChain()` to execute a sub-pipeline side-effect while automatically preserving the current value and context.
- **Context-Agnostic Composition**: Relaxed type requirements for `Work.then()` to allow merging context-agnostic blueprints (like `breakWork()`) into pipelines with any context type.

### Improvements & Bug Fixes
- **Pipeline Hardening**: Fixed issues where early termination (Break/Fail) would not correctly short-circuit subsequent stages in linear and nested pipelines.
- **Reliable SAGA Rollbacks**: Implemented `PipelineException` to ensure that `compensate()` actions are reliably executed in LIFO order upon failure, preserving the runtime context during rollback.
- **Null Safety**: Improved handling of `Optional` values in terminal stages to comply with RxJava 3 null-safety requirements.
