# RxOn v0.3.0-alpha Release Notes

## Lazy Orchestration Architecture
v0.3.0-alpha transitions RxOn from an eager RxJava wrapper to a purely declarative lazy orchestration engine.

### Core Changes
* **Lazy Execution**: `Work` pipelines are now deferred blueprints. Execution only occurs upon invocation of a terminal operator.
* **Zero-Nesting**: The API enforces flat pipeline structures, abstracting all RxJava primitives into sequential stages.
* **Functional Context**: Replaced mutable context objects with functional propagation. Context is initialized via `withContext(Supplier<C>)` and modified via `updateContext()`.
* **Scheduler Enforcement**: Internal stages now strictly use `WorkScheduler` mapping, configurable via `RxOnConfig`.

### API Refactoring
API components have been renamed for semantic consistency with the lazy orchestration model:
1. **Entry Points**: `fromIo()`, `fromRead()`, and `fromWrite()` renamed to `io()`, `read()`, and `write()`. Added `compute()` and `main()`.
2. **Chaining Operators**: Intermediate operators now use the `then` prefix (e.g., `thenIo()`, `thenCompute()`).
3. **Signal Observation**: `Monitor` renamed to `Observe`. Entry point `observe()` renamed to `flow()`.
4. **Nomenclature**: Internal references to "Blueprint" renamed to "Pipeline".

Refer to the [Migration Guide](../migrations/MIGRATION_0.2.2_TO_0.3.0-alpha.md) for upgrade instructions.
