# RxOn v0.3.0-alpha4 Release Notes

This release focuses on **API Symmetry**, **Streaming Parity**, and **Observability**. We have transitioned to a strictly explicit naming philosophy to eliminate ambiguity and provide a more predictable developer experience.

## New Features

### 1. Param-Based Chaining Symmetry
All `Work` and `Observe` chaining operators now use explicit parameter-based naming. This eliminates the "gate-prefixed" methods (e.g., `thenIoSingle`) in favor of unified operators that accept a `WorkScheduler`.
- `thenAction(WorkScheduler, ...)`
- `thenCallable(WorkScheduler, ...)`
- `thenFunction(WorkScheduler, ...)`
- `thenSingle(WorkScheduler, ...)`
- `thenMaybe(WorkScheduler, ...)`
- `thenCompletable(WorkScheduler, ...)`

### 2. Lazy Observe (formerly Stream)
The `Observe` class has been completely refactored into a lazy orchestration engine.
- Supports the same generic chaining symmetry as `Work`.
- Includes stream-specific operators: `thenFlowable`, `thenObservable`.
- Built-in lazy signal conditioning: `debounce`, `throttle`, `distinct`.
- Context propagation (`C`) across multiple emissions.

### 3. Advanced Control Flow & Composition
- **`breakIf(Predicate, defaultValue)`**: Declarative short-circuiting.
- **`failIf(Predicate, error)`**: Predicated error injection.
- **`zipWith(Work, Zipper)`**: Parallel orchestration of pipelines.
- **`peek(Consumer)`**: Non-intrusive side-effects.

### 4. Robust Recovery
- **Deep Cause Analysis**: `recover(Class, Function)` now recursively searches the exception cause chain, allowing targeted recovery even for wrapped exceptions.

### 5. Debugging & Monitoring
- **`tag(String)`**: Assign semantic names to pipelines.
- **`log(LogLevel)`**: Declarative logging of value and context.
- **Automated Lifecycle Logs**: Automated instrumentation of stage start/end and pipeline finish/error events when `debug` mode is enabled.

## Breaking Changes
- `Stream` class renamed to `Observe`.
- Removed legacy gate-prefixed methods (e.g., `readAction`, `writeCallable`).
- All entry points and chaining operators now require a `WorkScheduler` as the first argument.

## Bug Fixes
- Fixed non-deterministic emission order in streaming pipelines by switching to `concatMap` in the compiler.
- Fixed context loss during nested `thenChain` execution.
